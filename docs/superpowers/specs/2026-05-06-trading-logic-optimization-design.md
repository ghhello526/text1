# 交易逻辑优化设计文档

**日期**: 2026-05-06  
**模块**: `services/investment_strategy.py`

---

## 问题诊断

原代码存在一个核心 bug：`max_buy_count = max_consecutive_buy`（两者赋值为同一个参数），导致：

- 总买入次数和连续买入次数使用同一上限（默认5次）
- 买入累计达到5次后，**永远无法再次买入**，即使中间已经多次卖出
- 策略实际变成"单向加仓等清仓"，而非循环高抛低吸

---

## 优化目标

**混合循环策略**：核心仓位 + 剩余资金池循环高抛低吸

- 下跌时阶梯加仓（越跌投入比例越大）
- 上涨时按比例分批减仓
- 任意一次卖出后重置买入计数，可开启新一轮加仓（真正循环）
- 任意一次买入后重置卖出计数

---

## 核心变更

### 1. 移除总次数上限

| 旧 | 新 |
|---|---|
| `buy_count < max_buy_count`（限制总买入次数） | 删除，仅保留连续计数 |
| `sell_count < max_sell_count`（限制总卖出次数） | 删除，仅保留连续计数 |
| `buy_count`, `sell_count` 作为限制变量 | 改为纯统计变量（用于展示） |

### 2. 连续计数循环重置

```
卖出发生 → consecutive_buy_count = 0  （下一次买入从第1档开始）
买入发生 → consecutive_sell_count = 0  （下一次卖出从第1档开始）
```

### 3. 阶梯买入金额（动态）

旧：固定金额列表 `[1500, 1500, 1500, 1500, 1500]`

新：基于**当前现金**的比例，随连续次数递增

```python
BUY_RATIOS = [0.10, 0.20, 0.30, 0.40, 0.50]
buy_amount = cash * buy_ratios[consecutive_buy_count]
```

- 第1次连续买入：现金的10%
- 第2次连续买入：现金的20%
- ...（越跌投入越多）
- 卖出后重置，下一轮再从10%开始

### 4. 新增 `buy_ratios` 构造器参数

```python
InvestmentStrategy(..., buy_ratios=[0.10, 0.20, 0.30, 0.40, 0.50])
```

可选参数，有默认值，不影响现有调用方（`optimizer.py`、`main_window.py` 无需修改）。

---

## 不变的部分

- `SELL_RATIOS = [0.25, 0.25, 0.25, 0.25]`：每次减仓当前持仓的25%，逻辑不变
- `max_consecutive_buy` / `max_consecutive_sell`：上限含义不变，只是重置时机改变
- `reference_nav` 更新逻辑：每次交易后更新为当前净值（触发基准滚动）
- 清仓日强制全部卖出的兜底逻辑不变
- `StrategyResult` 数据结构不变，接口完全兼容
